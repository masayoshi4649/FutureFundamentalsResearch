# 主シナリオの数値整合

- [純計算補助](../research_support/scenario_consistency.py)で、本人が決めた中心経路と五択・想定帯を固定前に照合する。市場データの取得、方向・材料点・経路の生成はしない。
- 入力JSONの最上位は`as_of`、`session`、`scenarios`だけ。`scenarios`は`NK225`・`TOPIX`の両方を持つ。
- 各先物は`answer`、`center_vertices_pct`、`bounds_pct`だけ。頂点列は寄付き→順序付きの主な極値→終点をP0比％で本人が書く。省略した頂点間は連続移動とみなす。
- P0自体は場内高安へ足さない。寄付きのギャップを保ち、寄付き・終点を含む2点以上が必要。
- 帯は`open/high/low/end/range`を持ち、各値は`[min,max]`または`{"min":下限,"max":上限}`。最終actorの`analysis.scenario_bounds`と同値にする。
- もみ合い優先、最初の±0.5％到達、極値から0.5％反転は既存規約を使う。終点でP0を越える必要はない。境界は丸めない。
- 中心経路の分類が主回答と違う場合、本人が根拠を再検討する。プログラムの都合で経路や回答を作り替えない。
- 中心が帯内にあるかを検査する。帯の同時被覆率・任意の端点組合せ・未指定の道中の往復は評価しない。

```powershell
python -m research_support.scenario_consistency --input <本人の中心経路JSON> --judgment <最終材料判断JSON> --actor <最終担当JSON> --out <当回予測本文先/主シナリオの数値確認.json>
```

- 最終判断・actorを組み立てた後に実行し、反証後に回答や帯を変えたら未使用名で再実行する。入力・出力を上書きしない。
- 成功JSONは、本人入力・規約・補助コード・既存分類コードの原文とSHA、最終判断・actorのSHAを持つ。当回の本文固定対象へ含め、seal直前にも両最終SHAが一致することを確認する。
- 既存の予測・P0・ラベルは変更しない。導入前の中心経路を後付けしない。中心経路が整合しても、実市場での正解・値幅の包含・材料の因果支持は別に検証する。
