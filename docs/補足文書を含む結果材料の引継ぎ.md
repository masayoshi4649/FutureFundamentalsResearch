# 補足文書を含む結果材料の引継ぎ

- 第25場以降は別版 `local/本文遮断連続/結果材料を引き継ぐ_v2.py` を使う。旧版と旧出力は保存する。
- 必須の本文manifest・可知性照合・本人読了は、従来どおりJSON辞書・SHA・内容・時計を検査する。
- 任意補足のJSONも従来どおり辞書を要求する。壊れたJSONを文書扱いへ逃がさない。
- 任意補足の `.md`・`.txt`・`.py` は完全なバイト列のSHAを照合し、絶対パス・SHA・形式だけを出典へ残す。
- 補足本文を実行・記事化・時計解析しない。補足だけで新しい材料、可知時刻、読了を認めない。
- 未対応の形式、SHA不一致、必須JSONの代用品は拒否する。
- 原review・case・予測・採点は変更しない。第24の認定メモが任意出典として含まれた接続を扱う修正である。
- 次回入力に新しいhelperの原文・SHAを保存し、既存の本文切出・満了・検索上限を維持する。
- これは引継ぎの修正であり、予測精度の改善や80％達成の証拠ではない。
- 元の手順：[結果材料の引継ぎと検索](結果材料の引継ぎと検索.md)。
