# ブラインド検証で市場反応を更新する

- 予測担当には当回の時点入力と、その締切までの反応事例だけを渡す。次の担当は会話を継承しない。
- 順序は、予測固定 → 結果開示 → 同じ担当の振り返り固定 → 反応台帳へ追記 → 次回。
- 原予測・結果・振り返りを変更しない。同じ場を当たるまで予測し直して成績へ加えない。

## 保存する内容

- 一場を一事例とし、NK225・TOPIXの２観測を内包する。同じ場・共通材料を独立標本へ水増ししない。
- 材料群・物語ID・伝達経路、銘柄、P0、予測締切、総影響T、既反映B0、P0後増分D、寄与Q、残余を保存する。未知は `null` のまま。
- 予測時点で可視だった反応窓と、予測後の実際の評価窓を分離する。
- 主採点・全場参考・欠測・反転候補・臨時材料保留を保持する。終点の正負から反転順序を確定しない。
- 予測・実績・振り返りの内容ハッシュと、監査済み原本のファイルSHAを保持する。
- 材料と価格が同時に動いた観測は因果の実証ではない。反応事例から次の方向・％・確率を自動算出しない。

## 材料と価格の時計を比べる

- 開示後の当回CSVだけから、P0比±0.5％を最初に観測した足と、先行する別足の極値から0.5％反転を観測した足の時間帯を記録する。
- 反転が予定指標の公表前なら、分類が正解でも「指標の結果が反転の原因」とは判定しない。事前期待への先回りと、結果公表後の反応を別仮説にする。
- 足の開始・終了は約定の厳密時計ではない。欠測中の真の初回、同一足内の高安順序は補完せず、主採点や全場参考のラベルを変えない。
- 補足の保存：`python -m research_support.observed_reactions --root <価格開示済みの当回記録先>`。開示前・原CSVのSHA不一致・既存補足の上書きを拒否する。

## 次回への時点制限

- `simulated_end` と `simulated_review_at` が次回締切以前、かつ予測締切が次回より過去の事例だけを渡す。
- `recorded_at` は実際に台帳へ保存した時計。回想の `simulated_review_at` と分ける。`mode=運用` では実時計も次回締切以前に限る。
- `evidence_available_at` は**認定と考察の全根拠を利用可能になった再生時計**。単なる材料の発生時刻・記事公開上限ではない。根拠記事の取得・改訂・有効時計も確認して指定する。
- 根拠時計が不明または次回より後なら、全場の価格観測だけを渡し、主評価の認定と振り返り本文は渡さない。後日の保留認定で過去の教師を先回りして除かない。
- 根拠時計が可視でも、考察は次回確認する仮説・手順の候補。未確定を確定した市場法則へ変換しない。

## 最小の実行例

```powershell
python -X utf8 -m research_support.reaction_memory append --round <振り返り完了した場> --memory <台帳> --evidence-available-at <全根拠の最遅可視時計>
python -X utf8 -m research_support.reaction_memory snapshot --memory <台帳> --as-of <次回の時差付き締切> --out <未使用保存先> --keyword 原油 --channel 輸入費用 --limit 4
```

- 時計を確認できない初期事例は `--evidence-available-at` を省略し、観測専用で保存する。
- `append_reaction_case(round_path, memory_root, ...)` の返り値は保存した事例。ファイルは `cases/<case_id>.json`、内容識別は `case_hash`。
- `snapshot_memory(memory_root, as_of, out, ...)` は `snapshot.json` と短い `要点.md` を新規保存する。使用したsnapshotのSHAも次回予測の入力固定へ加える。
- 近い事例はキーワード、同じ `story_key`、伝達経路で照合し、場単位で選ぶ。一致点は検索順位であり勝率ではない。
- 台帳は追記のみ。再追記、元資料の変更、事例の書換え、監査にない事例を拒否する。訂正が必要な場合は原台帳を保持した別版を作り、来歴を明記して再検証する。
- テスト：`python -X utf8 -m unittest discover -s tests -p test_reaction_memory.py -v`。
