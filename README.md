## 基準価格と実行時刻

| 情報締切の候補 | 対象 | 騰落の基準 | 名目評価終点 |
| --- | --- | --- | --- |
| 07:45 | 当日デイ | 同じ先物の直前ナイト終値 | 当日15:45 |
| 16:00 | 次ナイト | 同じ先物の当日デイ終値 | 翌06:00 |

ナイト48,000→デイ48,500なら、07:45予測に対する結果は約+1.04%の上昇。現物指数の前日比は評価に使わない。

手元のCSVには引け板寄せ価格がないため、初版の基準・終点は前後セッションの最終1分足による代用。公式終了予定の10分以内であることを確認し、価格・時刻・代理である旨を記録する。これは厳密な取引所終値による評価とは区別する。

別監査で、次セッション名の生板に前場引け近傍の更新が残る例を確認した。[状態確認を含む補助観測](docs/前場引け近傍の状態確認.md)は第19場からの別入力とし、固定済みのP0・採点を置換しない。価格時計と受信時計、終値状態の確認と未確認を区別する。

情報締切 `as_of` と発行完了 `issued_at` を分ける。締切までの情報を使い、運用は５分以内かつセッション開始前に計算・発行を完了する。07:45／16:00の自動起動・通知先は検討段階で、このリポジトリから外部通知や注文は行わない。

## 操作

最初に価格の実在を確認する。

```powershell
python -X utf8 -m fundamentals inventory --prices ../FutureAlgorithmResearch --out local/価格調査.json
```

ニュース取得ツールの出力を `local/ニュース.json` として保存したら、改訂版を保持して原本へ取り込む。MCPの `structuredContent`、テキストJSON包み、記事配列、JSONLを読める。

検索結果は記事の発見に使い、必要な本文は同じ版IDの全ページを連結してから１記事として取り込む。版別原本には同じ記事版の検索抜粋と全文を重ねて取り込まず、同版の内容差は確認対象とする。原本フォルダ自体も `--news local/news` で読める。

```powershell
python -X utf8 -m fundamentals import-news --input local/ニュース.json --archive local/news
python -X utf8 -m fundamentals snapshot --news local/ニュース.json --as-of 2026-10-15T07:45:00+09:00 --out local/切出し01
```

切出した `snapshot.json` の可視記事だけから材料注釈を作成し、`local/材料.json` として保存する。過去の全期間本文をLLMへ読ませてから日時を絞る手順は、盲検検証にならない。

```powershell
python -X utf8 -m fundamentals forecast --prices ../FutureAlgorithmResearch --news local/切出し01/snapshot.json --events local/材料.json --as-of 2026-10-15T07:45:00+09:00 --out local/runs/予測01 --history local/runs --mode 回想
python -X utf8 -m fundamentals evaluate --run local/runs/予測01 --prices ../FutureAlgorithmResearch --observed-at 2026-10-15T15:45:00+09:00 --news local/ニュース.json
python -X utf8 -m fundamentals summarize --runs local/runs --out local/集計01
```

過去の例なので区分は `回想`。`運用` は実際の情報締切・発行時刻でのみ使用し、回想履歴を学習へ混ぜない。保存先は新規フォルダにする。予測本文、可視ニュース、使用材料、価格入力ハッシュ、コード版、学習に使った予測ID、対象時刻を固定保存する。ハッシュは変更検知であり、第三者の時刻証明ではない。

日程は昇順・重複なしの時差付き日時配列。例：`["2026-10-14T07:45:00+09:00", "2026-10-14T16:00:00+09:00"]`。

```powershell
python -X utf8 -m fundamentals walk-forward --prices ../FutureAlgorithmResearch --news local/ニュース.json --events local/材料.json --schedule local/日程.json --out local/反復01
python -X utf8 -m fundamentals review --run local/runs/予測01 --input local/考察.json
```

順次再生は予測→結果確定→評価→次時点の学習を反復する。評価終点が来ていない例、未来の評価記録は学習へ使わない。考察の修正案は次回以降に検証し、既存予測は上書きしない。

## 出力と現在の範囲

各先物について当日・１週間・１か月・３か月を保存する。長期は当日対象終点から７暦日／１暦月／３暦月先で、休場時は以後最初の同種セッションへ合わせ、ずれを記録する。

- 材料別点数：新規性、織込み、半減期を反映し、満期までの残存点数を対象先物別に集計。
- 数値推定：期間・日中夜間・先物を分けたリッジ回帰。最低12件かつ分類数の３倍以上が必要。少標本では方向を保留。
- 終点レンジ／経路レンジ：同じ基準価格定義による過去の経験分位。最低８件。将来の校正済み予測区間とは呼ばない。
- 評価：保留を含む全件分母、推定候補の方向一致、レンジ包含率、区間得点、誤差、後発材料候補、材料別の観測反応。

長期係数を日次リターンから外挿しない。標本不足のレンジ・確率は未算出。上昇確率を発行しない段階ではBrier得点も未算出。材料別の反応は同時発生要因を含む関連で、単独の因果効果ではない。後発材料を理由に外れた予測を全件成績から除外しない。

将来の拡張は、正式終値と限月・受信時刻の記録、期間別の前向き校正、個別株・指数ウェイトへの接続、材料失効と新規材料の寄与分解、定期通知の接続。現段階でこれらを実装済みとしない。
