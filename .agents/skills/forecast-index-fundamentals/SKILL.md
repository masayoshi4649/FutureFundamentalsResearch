# ニュースからNK225・TOPIX先物の見通しを研究する

このリポジトリのルートを作業場所とし、日本語で出力する。日次の予測を主に評価し、長期は材料別の寄与と残存の整合を確認する。初回または評価規約を変えるときは[研究設計](../../../docs/研究設計.md)を読む。実際のCLIとデータ契約は[README](../../../README.md)および `python -m fundamentals --help` で確認する。

## 現在の主評価：五分類

- **母集団の訂正**：９月21日以降の収録デイ・ナイトを全件列挙してから時点反復する。旧18回は９日×２場の限定日程であり、全価格期間の件数ではない。[全場台帳と選定経緯](../../../検証/00013_全セッションと材料の織込み/全セッション台帳.md)。P0不足・未実行も消さない。
- **ニュース判断の必須出力**：[材料の織込み点](../../../docs/材料の織込み点.md)に従い、材料別・先物別の総影響T、P0以前既反映B0、P0後増分D、P0基準寄与T−B0、asof以後残余T−B0−Dを根拠付きで表示する。未校正点を％・確率に変換せず、未知を０へ補完しない。
- **相場展開を先に判断**：[先物の展開予想](../../../docs/先物の展開予想.md)に従い、現在地→P0前後の新しい変化→主導材料→寄付き・継続／反転→終点・幅→反証を短く記す。古い負担と直近の改善を分け、材料の件数で多数決しない。直前上昇だけを好材料の消化完了とせず、小さい合計点をもみ合いの根拠にしない。当日８時半の市況記事を07:45へ遡及させない。
- 記事の転載・為替・海外株を同じ原因の別材料として重複加点しない。材料点を使わない過去頻度の代用をニュース予測として発行しない。五分類は使用材料IDと点の解釈・時間順序・反証条件へ結び付ける。
- **有効期間の追加規約**：予測時点で予定を知り得なかった大きな臨時材料が出た場合は、その公表前までを評価する。予定された指標・会見は新結果が予想外でも打切りに使わない。
- 材料の内容・事前予定・対象先物・最初の公表時計・影響根拠を、予測当否を見ない担当が台帳へ固定する。材料の大きさを外れた価格だけから決めない。
- 最初の該当材料で窓を終了し、公表時刻をまたぐ足を含めない。公表時計、分切下げの名目終点、実観測終点を分離する。開始前失効と材料認定不明は別に数える。
- 旧全セッション結果は参考として残す。固定済みの予測・計画・旧採点を上書きせず、未確定を正解へ変更しない。
- 各締切の学習用教師は、満了済みの過去場だけを再構成する。後日の記事による保留を過去の教師選別へ先回りして使わず、根拠全記事の収録版の公開・取得・有効時計を確認して次回から訂正する。
- [有効な規約](../../../docs/精度の合格条件.md)は場中に前セッション先物終値比±0.5％へ到達した回を対象とする。対象内の無回答は不正解。各先物で80％以上が目標。
- 回答は `上がる`、`下がる`、`上がってから下がる`、`下がってから上がる`、`もみ合い`。
- もみ合いは対象場の高安差が前終値比１％以内、かつ終点の前終値差が絶対0.5％以内。反転と重なっても優先して一つに分類する。
- 折返しは先行0.5％と高値／安値からの反転0.5％。終値で前終値を越える必要はない。複数往復は最初の±0.5％到達方向からの最初の反転を扱う。
- 場中高安へ前セッション終値自体を入れない。足内順序・欠測による未確定を正解や対象外へ勝手に変換しない。
- 新しい[五分類の別版手順](../../../research_support/README.md)で規約・実装・入力を固定する。旧 `fundamentals forecast`、`pdca_research`、`analyst_v2` の三分類を新五分類として発行・採点しない。
- 旧実験・予測は変更しない。新基準での精度は新規実験の固定回答から測り、旧横ばい±0.05％をもみ合いへ読み替えない。
- 以下の旧CLI例・循環１〜10は三分類の履歴とデータ準備用。入力の時点分離、先物基準、満了待ち、個別考察の原則は新規約でも維持する。

- ニュース源はユーザー指定の[ニュース取得ツール](plugin://dev-6a663c9c11fc8191948f5f21250d8144@created-by-me-remote)。利用可能なツールの一覧と実際の引数を確認してから取得し、提供されていない関数名を推測しない。まず取得対象・収録期間・取得可否を確認する。
- 価格は `../FutureAlgorithmResearch` の `candle_1min`、`candle_5min`、`book`。原本は読み取り専用で使い、商品・限月・足の時刻定義・収録期間を確認する。
- 学術知見は `S:/GitHub/masayoshi4649/MarketSkills/.agents/skills` の指数スキルと教科書索引から、今回の材料の伝達経路に必要な部分だけ読む。理論の符号や既存スコアを当日の実績係数に置換しない。

情報打切 `as_of` をタイムゾーン付きで固定する。定期実行候補は日中向け07:45、夜間向け16:00のJSTで、対象セッション開始の1時間前である。起動予定、情報打切、注釈完成、発行完了 `issued_at` は別に保存する。運用では情報打切後に切出済み情報だけを注釈し、発行を情報打切から5分以内かつ対象セッション開始前に完了させる。超過時は運用発行を拒否するか、新しい情報打切でやり直し、回想へ切り替えて運用実績にしない。

公開、初回確認、改訂、価格対象、結果取得の時刻も区別する。完了前の足、後日改訂記事、情報打切後に判明した材料を予測入力へ渡さない。注釈は発行完了以前、記事の利用可能時刻と材料の既知時刻は情報打切以前とする。

騰落の基準は同じ先物の前セッション終値とする。07:45は直前ナイト終値→当日日中終点、16:00は当日日中終値→次ナイト終点を予測する。ナイトで暴落した後に日中反発した場合は、現物前日比がマイナスでも日中予測は上昇として扱う。元CSVにオークション終値がなければ、公式終了予定までの最終1分足を10分以内に限って代理と明記し、その時刻を示す。現在の基準価格・評価価格は `candle_1min` に統一し、学習事例も同じ基準へそろえる。

## 予測を作り固定する

1. `inventory` で価格の実在・収録状況を確認する。必要本文は原本JSONへ保存し、予測担当へ表示する前に、別の入力準備役が主文の意味時点と連続区間を確認する。予測担当には切出本文だけを渡し、未切出の原文・検索抜粋・関連記事・AI生成欄を表示しない。同じ版の本文ページは順番に連結して１記事にし、版別原本へ同じ版の抜粋と全文を重ねて取り込まない。`import-news` で版別原本へ追記できる。
2. `snapshot` で情報打切までのニュースを機械的に切り出し、その結果だけを構造化担当へ渡す。現行選別は取得時刻も制約する運用時点の再現であり、後日取得記事を公開時刻だけで遡及利用するモードはない。未来本文が既に同じ文脈へ入った試行は回想・非盲検の動作確認とする。
3. 切出済み記事を材料群へまとめ、カテゴリー、局面、指数別の影響、確信度、新規性、織込み、半減期、根拠記事の識別子と改訂を構造化する。直前セッションで既に織り込んだ分と次セッションへの追加反応を分ける。これらの採点は根拠付き注釈として作成できる。価格・公表実数・観測事実の欠損を推測値で埋めない。実際の `events` スキーマへ合わせ、注釈の作成時刻と版を保存する。

現在の材料表には別版 `research_support/material_points.py` を用いる。旧掛け算形式の点をTへ入れて既反映を再控除しない。時点入力の切出は `research_support/prepare_material_snapshot.py` で行い、全場の入力準備・予測固定・結果評価を別件数で管理する。

材料判断では切出記事の時計・見出し・元抜粋を保持し、本文を別取得した場合は同じ記事ID・版、原本SHA256、使った主文区間を保存する。`python -m research_support.material_report --help` の別版入口で原P0・記事・本文を照合し、予測を固定してから結果を開示する。点数を入力しただけで判断が完成したとせず、五択に使った材料ID・点の解釈・初動と反転・反証条件も固定する。
4. `forecast` で当日・1週間・1か月・3か月の見通しを作り、実際の発行完了を記録する。当日の名目終点は日中15:45／夜間翌06:00の公式終了予定とする。CSVの最終足が15:40前後／05:55なら許容10分以内の代理と明記し、クロージング・オークション価格を補わない。長期は当日の公式終了予定から7暦日・1暦月・3暦月先の名目期限と、それ以後の最初の同種セッション完了時点を分ける。過去結果を使う場合は、現在の情報打切までに予測発行・評価終点・評価記録がそろう運用履歴だけを渡す。
5. 予測、入力、モデル・規則の版、対象時刻を新しい実行ディレクトリへ保存し、既存予測を上書きしない。新情報による再予測は別の実行として結び付ける。

本文にナビゲーション・後日の関連記事・時点不明の銘柄表が混在する場合は、原本を保持したまま主文の区間を明示して分離する。分離や当時版の来歴を確認できなければ、その部分を過去の予測へ渡さない。公表・取得時計だけの検査で本文全体の時点整合を保証しない。[追加ソースで確認した例](../../../検証/00008_ニュース源の追加点検/README.md)の実績・予想・改訂前値・材料発生時計は別の項目で保存し、欠測を補完しない。

全文を一度表示してから利用区間を限定した試行は、表示前の本文遮断を満たしたことにしない。時点不明の主文本体は全体を不採用にし、除外理由にも未知の題名・事実・数値を引用しない。`research_support.material_judgment` は明示した点・方向・根拠・区間を既存形式へ配線する補助であり、事前切出の代わりにはしない。

`research_support.actor_judgment` は本人が確認したID・版、実読範囲、６項目の事実申告、分析を受け取り、担当記録のID・SHA・件数・可知価格を配線する。読了や安全値を自動で作らず、独立標本数未認定のnullも保持する。[使用例](../../../research_support/actor_judgment使用例.md)に従い、当日幅の想定は先物別の寄付き・高値・安値・終点・高安差の[min,max]を本人入力として残す。未知を数値補完せず、範囲の反証と５分類採点を分ける。

予測・認定へ渡す見出し資料は、本文・抜粋欄を持たない別ファイルとして先に作る。元packetや認定入力の全体を表示せず、記事ID・版・見出し・URL・存在時計等を明示した許可項目だけ写す。元packetは照合・組立の内部だけで読み込む。現在の連続検証では `local/本文遮断連続/表示用メタデータ.py` が予測用資料を作り、元入力と補助コードのSHAも残す。

主文の途中に関連記事が入る場合は、同じ原本・記事版の連続区間を別々に保存する。[複数区間の固定入口](../../../local/本文遮断連続/固定と更新_複数区間.py)は全区間を固定し、使用本文が単一の承認区間内に収まることを検査する。除外部分をまたいだ連結、重複区間、別原本への付替えは拒否する。既存の固定入口と固定済み予測は変更しない。

[市場営業日の条件](../../../docs/市場営業日の条件.md)を確認し、現物休場・先物の祝日取引・海外市場の開場を分ける。現物の業種波及を観測できないことを、弱い反応や狭幅の証拠にしない。制度資料は公表日と原本SHAを持つ別入力にし、ニュース材料の増分点と混ぜない。

[終値代理と引け板寄せ](../../../docs/終値代理と引け板寄せ.md)を区別する。15:40・05:55の代理値を15:45・06:00の引け板寄せ価格と同一視せず、引け準備時間と通常取引中の不足も説明上分ける。未知の引け値やDを補完せず、制度注記だけを理由に固定済みのP0・ラベル・分母を書き換えない。

次セッション名の生板に残る前場引け近傍の更新は、[状態確認を含む別観測](../../../docs/前場引け近傍の状態確認.md)として扱える。価格時計を予定終端へ丸めず、状態1・8・23を確認できない候補は価格を表示しない。受信時計・同限月・後続訂正の未確認を残し、既存の基準価格や国内D点を自動置換しない。

[足の未収録と無約定](../../../docs/足の未収録と無約定.md)も区別する。足の確定フラグや出来高の完全フラグから、全価格経路の収録を推定しない。現行の生板JSONLには受信時計・連番が残らないため、無約定と通信停止の識別には別の証拠が必要になる。

外部市場の観測時刻がそろわない場合は[外部市場の同期比較](../../../docs/外部市場の同期比較.md)を参照する。[外部市場観測ビュー](../../../docs/外部市場観測ビュー使用例.md)で後日取得した履歴と当時の配信記録を区別し、確定足・表示余裕・古さを照合した別表示だけを予測へ渡す。外部価格を国内先物の既反映点へ自動換算せず、採用回以前の予測は変更しない。

[CME日経先物](../../../docs/CME日経先物の補助観測.md)と[米半導体・MU](../../../docs/米半導体の補助観測.md)は、用途ごとの鮮度・実足時計を示す補助観測にする。[P0との時計照合](../../../docs/外部市場とP0の時計照合.md)では「P0当時に利用可能だった古い足」と「締切までに利用可能になったP0同終端の足」を分ける。P0と時計・限月が異なる絶対価格差を、国内先物の寄付きや織込み点へ直結させない。

[配当と先物の基準価格](../../../docs/配当と先物の基準価格.md)を確認する。先物に事前控除される予想配当と、再投資の需給仮説を分け、現物の機械的な配当落ちを先物のP0後の下落へ転記しない。

基本形は次のとおり。利用前に各サブコマンドの `--help` とREADMEで最新の引数・形式を確認する。

```powershell
python -m fundamentals inventory --prices ../FutureAlgorithmResearch
python -m fundamentals import-news --input <ニュースJSON> --archive local/news
python -m fundamentals snapshot --news <ニュースJSON> --as-of <タイムゾーン付き日時> --out <切出先>
python -m fundamentals forecast --prices ../FutureAlgorithmResearch --news <切出先/snapshot.json> --events <材料JSON> --as-of <タイムゾーン付き日時> --out <新規実行先> --history runs --mode 運用
```

`forecast` の既定モードは回想である。前向きの定期予測には `--mode 運用` を明示する。過去再生は `--mode 回想` または回想専用の `walk-forward` を使い、運用成績と分離する。

初期段階で係数が不足するなら方向優位性は未検証として保留し、同時刻・同セッションの価格経験分布によるレンジと材料の定性方向を区別する。期間別の標本が足りなければレンジも算出不能とする。各期間を別学習し、日次の変動を平方根時間で長期へ外挿しない。未校正の材料点数を確率、勝率、百分率リターンとして表示しない。首位を50%超へ押し上げる処理は行わない。

## 結果を評価し次へ渡す

継続的な再生は[本文を先に遮断する検証](../../../検証/00016_本文を先に遮断する連続検証/README.md)に従う。各場の事前本文切出→予測固定→独立材料認定→実績開示→同じ予測担当の振り返り→[市場反応台帳](../../../docs/市場反応の更新.md)の追記・固定→次回用snapshotの順で進める。振り返りと反応の更新が終わるまで次場へ進まない。

結果開示後は `python -m research_support.observed_reactions --root <当回記録先>` で、観測上の±0.5％到達足と、先行する別足の極値から0.5％反転した足の時間帯を補足できる。材料・予定指標の時計と比較し、分類の正解と理由の妥当性を別に振り返る。公表前に観測済みの反転を公表結果の効果にしない。欠測中の真の初回や足内順序は補完せず、元ラベルを変えない。

[結果ニュースによる反応の更新](../../../docs/結果ニュースによる反応の更新.md)では、結果開示後に同じ担当が予定指標の実績や窓内材料を選び、場の終了で別途切り出した本文を読む。実績を未読のまま原因不明として終えず、予測時点の予想・直前予想・実績・公表前後の観測反応を区別する。新根拠のSHA・実読・時計を`review_evidence`へ結び、検索用の材料キーと次回条件を`market_reaction_updates`に保存する。予測や当初の材料点へ遡及追記しない。

[結果材料の引継ぎと検索](../../../docs/結果材料の引継ぎと検索.md)は、元caseを変更せず、原review・新根拠・本人実読をSHAと時計で辿って別viewへ付加する。通常の直近12場と、本人が事前指定した材料検索の追加最大６場を一つの上限として守る。結果材料は過去場の観測であり、元の予測時点の既知材料へ遡及しない。該当記事や更新が０なら捏造せず、検索・不採用理由を残して旧reviewだけを引き継ぐ。

第25場以降は[補足文書を含む引継ぎ](../../../docs/補足文書を含む結果材料の引継ぎ.md)の別版を用いる。必須JSONは従来の厳密照合を保ち、任意の文書は同一SHAだけを確認して材料・時計の根拠へ読み替えない。

[同じ場の観測幅](../../../docs/同じ場の観測幅を比較する.md)も当回の承認viewから直近最大６例を比較する。本人は中心幅・想定帯を実数で照合し、収縮を見込む根拠と広幅になる反証を記す。観測幅の下限・中央値・最大を真の通常幅や予測区間・80％包含へ読み替えず、過去幅へ機械的に合わせない。

[発表近傍の観測](../../../docs/発表近傍の観測.md)は開示後の本人先指定に限る。実公表不明なら予定窓として表示し、P0比・直前観測値比・実足時計・欠測を分ける。厳密な終端足のない反応値を補間しない。

固定前には[主シナリオの数値整合](../../../docs/主シナリオの数値整合.md)を確認できる。本人が指定した寄付き・順序付き極値・終点から、五択と想定帯の整合を検査し、最終判断・担当記録へSHAで結び付ける。数値の整合と実市場の予測精度は分けて評価する。

次の予測・認定担当は履歴を継承しない。予測は当回締切まで、認定の既知比較は当回締切まで、窓内材料は当回終了までで本文を切り出す。材料・直前状態・先物別の反応・欠測・未確定・次回の修正を残し、参照case IDの共通条件と相違点を判断へ反映する。後日の認定や根拠時計不明の考察を過去へ渡さず、単発の観測を因果法則や勝率にしない。00016は空の反応台帳から全39場（P0不足１・予測38）を再生し、遮断を保証できなかった旧試行の主観情報や成績を混ぜない。同じ場の再試行を独立標本として加算しない。

[過去反応の再利用](../../../docs/過去反応の再利用.md)に従い、採用事例の原文条件まで読む。古い同系材料は本人が検索目的を先に指定して追加取得し、的中で選ばず、検索範囲と上限を固定する。反転の有無・量・終点を分け、振幅だけを修正して同じ分類を維持する案も比較する。

発行前の別担当は[反証の判断基準](../../../docs/反証の判断基準.md)に従い、規約違反・事実誤読・積極的な反証・未識別の不確実性を分ける。指摘は最大３点・０点可とし、不確実という理由だけで原案の撤回を強制しない。本人の採否を保存し、結果開示後に草稿と正式回答を同じ規約・分母で別比較する。

過去を順次検証する依頼では、新しい検証フォルダを作り、[反復処理](../../../fundamentals/replay.py)の `prepare_round` → `seal_prediction` → `review_round` の開示 → 同関数の振り返り、を時系列で繰り返す。予測担当には切出済み `masked/packet.json` と静的な指示だけを渡し、過去の会話を継承しない担当を各回に使う。担当者・入力・予測・開示・振り返りの証跡を保存する。完了した振り返りだけを次回へ渡し、採用した対応を原文で記録する。

各回は短い `予測.md` と `振り返り.md` を箇条書き主体で残す。既存レポートを読ませて予測を作り直さない。全回終了後に `summarize_replay` で全件集計、`track_long_term` で未満了だった長期を別追跡する。手順の時点整合と、予測精度の優位性は別に判定する。[実施例](../../../検証/00001_時点を区切った反復検証/README.md)を参照できる。

精度の最低目標は[対象回の五分類正解率80％以上](../../../docs/精度の合格条件.md)。未達の方式を完成扱いにしない。PDCAではレポートの追記にとどめず、失敗診断→予測規則・数値係数の変更→別実験での予測固定と結果開示→基準比較まで実行する。既知期間での改善は開発結果とし、未使用期間による確認と区別する。

固定した材料注釈から係数更新を試す回想実験には `python -m fundamentals.pdca_research --help` を使える。`--initial-history` の全教師は最初の情報締切より前に満了させ、初期教師を評価分母へ加えない。標準化統計は各締切の過去学習行だけから計算する。[改善循環の進捗](../../../検証/PDCA進捗.md)で採用状態を確認する。回想専用の履歴条件を運用時の既観測履歴と同一視しない。未使用期間の予測担当は各締切で独立させ、後の入力を同じ文脈へ渡さない。

既反応量の実測と方向分類の開発比較には `python -m fundamentals.pdca_measured_research --help` を使える。直前先物の騰落・終値位置・末尾窓の実観測を保存し、欠測を完全な期間変化と呼ばない。ニュースの実数は根拠記事へ結び付け、日付・前日値の不整合を推測補完しない。クラススコアを確率・百分率へ変換しない。[循環７〜９](../../../検証/00005_実測した既反応と分類/README.md)は全て不合格であり、運用方式へ切り替えない。

全文と実測状態を担当が直接判断する新しい反復には、[個別考察を必須にした別版](../../../research_support/README.md)を使う。担当の静的指示に横ばい境界を明記して準備時に検査し、予測固定→満了後の結果開示→同じ当回担当の個別考察固定を分ける。考察が確定するまで次の締切へ進めず、予測根拠と考察根拠を別々に引き継ぐ。原採点と当回採点を混ぜない。[旧版の18回](../../../検証/00006_全文と実測反応による直接判断/README.md)は8/18・7/18で不採用であり、別版の精度改善はまだ実証していない。

当日の日中・夜間セッションの公式終了予定が過ぎてから `evaluate` で結果を取得する。最終足が早くても15:45／翌06:00前に満了扱いにしない。終点未到来、許容代理も含めた価格欠損、限月不整合なら評価を保留し、任意の直近値で穴埋めしない。集計には `summarize`、時系列の反復には `walk-forward`、知見候補の追記には `review` を使い、予測後に得た結果が過去の予測へ戻らない順序を保つ。上昇確率を発行できない段階ではBrier得点を算出しない。

ローカル未収録の満了場は、[当日価格の追加取得](../../../docs/当日価格の追加取得.md)で親リポジトリ記載の読取APIを確認できる。原価格へ書き込まず、別ルートへAPI原本・取得時計・過去CSVのコピーハッシュを保存する。別セッション、未来のスナップショット、未確定足、末尾不足を拒否し、任意の長期履歴が得られるとは仮定しない。[検証で得た知見](../../../docs/検証で得た知見.md)へ根拠と採否を残す。

```powershell
python -m fundamentals evaluate --run <実行先> --prices ../FutureAlgorithmResearch --observed-at <結果取得日時> --news <予測後ニュースJSON>
python -m fundamentals review --run <評価済み実行先> --input <考察JSON>
python -m fundamentals summarize --runs runs
python -m fundamentals walk-forward --prices ../FutureAlgorithmResearch --news <ニュースJSON> --events <材料JSON> --schedule <時系列JSON> --out <新規反復先>
```

当たり外れの説明は、後発材料候補、既知材料の取得漏れ、解釈・織込み・期間の誤り、価格・需給の誤り、データ不備、原因不明へ分ける。後発記事の存在だけでは値動きの原因と断定できない。予定指標の結果は未知でも、発表予定とイベントリスクは既知だった場合がある。

後発材料があった予測も全件成績へ残す。当たった理由も反証を確認し、単発の成功・失敗は知見候補として保存する。規則の変更は次の予測から適用し、同じテストを当たるまで繰り返して検証済みにしない。試した係数・窓・半減期と不採用結果も履歴へ残す。

長期は元の材料群を固定したまま、残存・失効・反証と新規材料を分ける。今回の銘柄別ポイントは対象のNK225・TOPIX別とする。個別株からの集計には企業別の根拠と基準時点の指数ウェイトが必要であり、指数別 `impacts` だけで個別株別の実証が完了したと表示しない。

## 利用者へ返す内容

基準日時と情報打切、商品・限月、前セッション基準価格・時刻・代理の有無、対象日時、データ期間を示し、2指数×4期間の方向・百分率レンジ・検証状態を表にする。終点の帯と期間中の高値安値の帯は分けて表記する。出せない数値は不足理由を示す。

続けて主要材料、指数ごとの伝達経路、織込みと反証条件、前回から追加・失効した材料、当日の評価、蓄積件数と基準モデルとの差を簡潔に記す。優位方向の保留率と探索的な候補方向の一致率を分け、候補を出した後の横ばいを一致率の分母から外さない。材料点数、経験分布、実績校正済み予測を区別し、前向き成績、回想検証、合成動作試験を混ぜない。

このスキルは研究と見通しの更新を行う。07:45／16:00の定期実行と外部通知は候補段階で未設定である。実行環境側で時刻が設定された場合は同じ流れを呼び出す。ユーザーから依頼されていない外部発信や自動注文を追加しない。
